成果主義の限界と、組織で成果を出す設計

最終更新 2026-08-27

個人インセンティブを効かせた営業組織で、ある時期から同じ症状が現れます。トップセールスのやり方が誰にも共有されない。良い案件は取り合いになり、新人は誰にも助けてもらえない。期末には駆け込み受注と値引きが乱発される。これらを「うちの営業はギスギスしている」という文化の問題として語る経営者は多いのですが、実態は違います。制度が個人の短期数字だけに報いているなら、メンバーは制度に対して合理的に振る舞っているだけです。この記事では、成果主義を捨てずに、その副作用を設計で抑え、組織として成果を出す評価・目標の組み立て方を解説します。

成果主義は悪ではない。問題は「何に報いるか」の設計

最初に立場を明確にします。営業に成果への報酬は必要です。成果を出しても出さなくても処遇が変わらない組織では、優秀な人材から順に流出します。年功や情実への揺り戻しは、成果主義の副作用よりはるかに深刻な病を生みます。

問題は成果主義か否かの二択ではありません。「成果」として何を定義し、何に報いるかの設計です。多くの営業組織で「成果」は、事実上「個人の・今期の・受注金額」に縮約されています。個人単位で、単期で、金額だけ。この3つの縮約それぞれが、固有の副作用を生みます。

個人単位への縮約は、同僚を協力相手ではなく競合に変えます。単期への縮約は、来期以降の価値を評価の外に追い出します。金額だけへの縮約は、その金額がどう作られたか——値引きで作ったのか、無理な受注で作ったのか——を問わなくします。

つまり「成果主義の弊害」と呼ばれているものの正体は、成果主義そのものではなく、成果の定義が狭すぎる設計の弊害です。この区別ができると、打ち手は「成果主義をやめる」ではなく「成果の定義と報い方を設計し直す」に変わります。

個人の短期数字だけに報いると何が起きるか

設計の副作用は、抽象論ではなく具体的な行動として現れます。個人インセンティブ中心の営業組織で観察される典型的な症状を挙げます。

  • ナレッジを共有しない — 自分の勝ちパターンを教えれば、教えた相手が社内ランキングの競合になる。共有は評価上の自傷行為であり、抱え込みが最適解になる
  • 案件の取り合いと押し付け合い — 確度の高いリードは奪い合い、手間のかかる小口や難しい顧客は押し付け合う。担当割りのルールの隙間で消耗戦が起きる
  • 新人を助けない — 新人への同行や相談対応は、自分の数字を1円も増やさない時間。育成協力は「善意のある人が損をする」構造になる
  • 期末の駆け込みと先送り — 目標達成が見えたら受注を翌期に回し、未達なら値引きしてでも今期に詰め込む。数字が顧客の都合ではなく評価の締め日で動く
  • 不都合な情報の隠蔽 — 失注理由やクレームの兆候を報告すれば自分の評価が下がるだけなら、報告しないのが合理的。組織の学習が止まる

ここで重要なのは、これらはすべて人格の問題ではなく、設計への合理的反応だということです。抱え込みをする社員は利己的なのではなく、共有に報酬がなく競争に報酬がある制度の下で、正しく計算しているだけです。

「協力しよう」「チームで戦おう」という呼びかけで行動が変わらないのは、このためです。理念と制度が矛盾するとき、人は理念ではなく制度に従います。制度が競争だけに報いれば、競争だけが起きます。行動を変えたいなら、説くべきは理念ではなく、直すべきは設計です。

設計①：個人成果と組織貢献の二階建て評価

最初の設計は、評価を二階建てにすることです。1階に個人の成果、2階に組織への貢献。個人成果の評価は維持したまま、共有・支援・育成協力といった組織貢献を、評価の言語に正式に載せます。

組織貢献を評価に載せるときの要点は、「協調性」のような性格評価にしないことです。性格は測れず、測れない評価は情実に流れます。評価するのは、事実として確認できる行動です。

貢献の種類事実として確認できる行動の例確認の手段
ナレッジ共有勝ちパターン・失注分析の共有回数と、他メンバーによる活用実績共有の記録、活用した側の申告
案件支援他メンバーの商談への同行・提案レビューの実績同行記録、支援を受けた側の申告
育成協力新人のOJT担当、ロープレ相手、質問対応の実績と新人の立ち上がり育成記録、新人の成果推移
組織への情報提供失注理由・市場情報・競合情報の報告の質と量SFA上の記録

配分の目安として、組織貢献の比重は評価全体の2〜3割程度から始めるのが現実的です。少なすぎれば無視され、多すぎれば「売らなくても評価される」という別の歪みを生みます。

もうひとつの要点は、貢献の受け手からの申告を評価材料に入れることです。「Aさんの同行のおかげで受注できた」という受益側の事実申告は、本人の自己申告より信頼でき、かつ「助けてもらったら申告する」文化そのものが協力を可視化します。なお、管理職自身の評価に育成や再現性を入れる設計は別記事で詳述しましたが、メンバー評価に組織貢献を入れる本設計とセットで機能します。管理職だけ、あるいはメンバーだけを変えても、評価の言語は組織に定着しません。

設計②：チーム目標の併用と「配合」の考え方

二つ目の設計は、目標の持たせ方です。個人目標だけの組織では、隣の未達は自分に無関係です。そこで個人の処遇の一部を、チーム目標の達成に連動させます。チームが達成すれば全員に上乗せがある。この瞬間、隣のメンバーの数字が自分事になり、支援と共有に経済合理性が生まれます。

ただし、振り子を反対側に振り切ってはいけません。全部をチーム連動にすると、今度はフリーライドが起きます。誰かが頑張れば自分も報われるなら、頑張らないのが合理的になる。個人の緊張感とチームの協力は、どちらか一方ではなく配合の問題です。

配合を考える目安を示します。

  1. 基本は個人主・チーム従 — 変動部分のうち個人連動を7、チーム連動を3程度から始める。営業は個人の裁量と行動が成果に直結する職種であり、個人の柱は残す
  2. チームの規模で調整する — 連動させるチームは5〜10名程度の顔が見える単位にする。全社連動は一人の貢献実感が薄すぎて、協力のインセンティブとして機能しない
  3. 分業度で調整する — インサイドセールスとフィールドセールスの分業のように、成果が構造的に共同作業である組織ほど、チーム連動の比率を上げる
  4. 運用しながら症状で微調整する — 抱え込みが残るならチーム比率を上げ、手を抜く人が現れたら個人比率を戻す。配合は一度で正解に当たるものではない

チーム連動を入れると「自分は達成したのにチーム未達で報酬が減った」という不満が必ず出ます。これには設計思想を正面から説明します。個人達成分は個人連動部分で報いている。チーム連動部分は「チームを達成させる行動」への報酬であり、自分が売ることだけでなく、隣を助けることも含めてその対象である、と。この説明ができない配合は、設計者自身が思想を詰め切れていません。

設計③：数字の作り方を問う——プロセスの健全性の担保

三つ目の設計は、成果の「質」を評価に組み込むことです。同じ受注1,000万円でも、標準価格で顧客の課題に合致した受注と、大幅値引きと過剰な約束で押し込んだ受注は、会社にとっての価値がまったく違います。後者は粗利を毀損し、導入後のクレームと解約を仕込み、値引きの前例として翌期以降の価格交渉を不利にします。

金額だけを見る評価は、この二つを区別しません。区別しない評価の下では、押し込みが合理化されます。だから、質の悪い成果に報いない仕組みを評価に併設します。

実務的な担保の方法は3つあります。第一に、値引きの評価反映。達成率を受注金額ではなく粗利ベースで計算する、あるいは標準価格からの乖離率を評価の調整項目にする。値引きで作った数字の評価上の旨味を消します。

第二に、受注後の結果の遡及。受注から一定期間内の解約・大幅なクレーム・未回収は、受注時の評価から控除する、あるいは翌期の評価で減点する。「売ったら終わり」の受注と「定着まで見た」受注の評価を分けます。

第三に、プロセス逸脱の下限設定。コンプライアンス違反や虚偽説明はもちろん、社内ルールを逸脱した受注は、金額にかかわらず評価対象から外すことを明文化する。上限のインセンティブと同時に、下限の規律を制度に書き込みます。

質の担保は「数字が全てではない」という精神論で語ると失敗します。営業現場は精神論を聞き流す訓練を積んでいます。粗利ベースの達成率、解約の遡及控除のように、計算式そのものに質を織り込むこと。計算式に入っていないものは、現場では存在しないのと同じです。

成果の定義を時間軸で広げる

ここまでの3つの設計に通底するのが、成果の定義の問題です。最後にもう一段掘ります。今期の受注だけが成果なのか。

営業が生む価値には、時間軸の長いものが含まれます。既存顧客の継続と更新。取引の深耕による単価の向上。満足した顧客からの紹介。これらは今期の新規受注より再現性が高く、獲得コストが低い、質の良い売上です。ところが「個人の・今期の・新規受注」に縮約された評価は、これらをほとんど評価しません。

結果として、更新前の既存顧客へのフォローより新規のテレアポが優先され、紹介を生むような丁寧な導入支援は「数字にならない仕事」として省かれます。LTV型のビジネス——サブスクリプション、リピート受注、保守契約——であるほど、この歪みは損益に直結します。

評価に時間軸を入れる方法はシンプルです。継続率・更新金額・紹介経由の受注を、新規受注と並ぶ評価項目として明示的に立てる。担当顧客の年間取引額の推移を個人の成果指標に加える。ビジネスモデル上、顧客の継続が利益の源泉なら、評価の重心もそこに寄せる。評価の時間軸は、ビジネスモデルの時間軸と揃っているのが正常な状態です。売り切り型の評価設計のままLTV型のビジネスを運営している会社は、制度が事業の足を引っ張っています。

制度変更の進め方：一気の改革は失敗する

設計が描けても、移行を誤ると制度は定着しません。成果主義の再設計で最も多い失敗は、正しい制度を一気に導入して、組織の反発で頓挫するパターンです。

忘れてはいけないのは、現行制度には勝者がいることです。個人インセンティブで高収入を得ているトップセールスにとって、チーム連動や組織貢献評価の導入は、実質的な減収の脅威に映ります。そして彼らは、組織で最も転職市場価値が高い層です。配慮なき改革は、最初にエースを流出させます。

実務的な進め方は、次の順序です。まず、現状の症状を事実で示す。ナレッジ共有の実績、案件配分をめぐるトラブル、期末の値引き率の跳ね上がり、新人の立ち上がり期間。制度変更の必要性を、理念ではなくデータで組織に共有します。

次に、移行期間と経過措置を設計する。初年度は組織貢献評価を「加点のみ」で運用し、減点には使わない。チーム連動は小さい比率から入れて段階的に上げる。現行制度での高評価者には、移行後の一定期間の水準保証を検討する。制度の意図を伝える期間を確保してから、本格運用に入ります。

そして、トップセールスを設計に巻き込む。彼らの勝ちパターンこそ組織が共有したい資産であり、新制度は「教える人が最も報われる制度」として彼らに提示できます。ナレッジ提供者・育成協力者として新制度の最初の受益者になってもらえれば、最大の抵抗勢力は最大の推進力に変わります。

最後に、制度は一度作って終わりではありません。導入後も症状を観測し続けてください。抱え込みは減ったか。フリーライドは出ていないか。値引き率は下がったか。評価制度は組織の行動の設計図であり、設計図は運用の実態を見て引き直すものです。成果主義の限界とは、成果主義の終わりではなく、設計の解像度を上げる出発点です。個人が強く、かつ組織として強い。その両立は文化への祈りではなく、設計で作れます。

よくある質問

組織貢献の評価は、結局は上司の主観にならないでしょうか?

「協調性がある」のような性格評価にすれば主観になります。防ぐには、評価対象を事実として確認できる行動——共有の記録、同行の実績、受益者からの申告——に限定してください。特に「助けてもらった側の申告」を材料にすると、評価者の観察だけに依存しない多面的な事実が集まります。主観を排除するのではなく、事実で裏づけられた判断に変えるのが目標です。

チーム連動を入れると、優秀な人ほど不公平だと感じませんか?

個人連動の柱を残す配合であれば、優秀な人の個人成果は引き続き個人部分で報われます。そのうえで、チーム連動部分は「隣を強くする行動」への報酬だと明確に説明してください。実際、トップセールスがナレッジ提供や育成協力で貢献すれば、チーム連動と組織貢献評価の両方で最も報われる立場になれます。不公平感の多くは、設計思想の説明不足から生じます。

小規模な組織で、精緻な制度を作る余力がありません。何から始めるべきですか?

制度の精緻さより優先すべきは2点です。第一に、粗利ベースの達成率への変更。値引き乱発の抑制は計算式の変更だけで効きます。第二に、組織貢献の「加点」の明文化。共有・支援・育成協力を評価で必ず言及する項目にするだけで、行動は変わり始めます。二階建ての配点設計やチーム連動は、この2つが回ってからで十分です。

期末の駆け込みや翌期への先送りは、どう抑えればよいですか?

完全にはなくせませんが、設計で減らせます。評価期間を四半期偏重から年間基調に寄せる、達成率のカーブを「100%ちょうどで報酬が跳ねる」段差型から滑らかな形にする、粗利ベース評価で期末値引きの旨味を消す、の3つが有効です。段差型の報酬カーブは、締め日直前の数字の操作を最も強く誘発する設計です。

評価制度を変えずに、運用だけで協力を生むことはできますか?

限定的には可能です。案件配分のルールを明文化して取り合いの余地を減らす、共有会を業務時間内に定例化する、管理職が支援行動をその場で言語化して承認する、などです。ただし、制度が個人の短期数字だけに報い続ける限り、運用の工夫は制度の重力に負けていきます。運用の改善は移行期の橋としては有効ですが、最終的には評価の計算式そのものに手を入れることをお勧めします。

この記事のまとめ

  • 問題は成果主義そのものではなく、成果が「個人の・今期の・受注金額」に縮約された設計の副作用
  • 抱え込み・案件の取り合い・新人放置・期末の駆け込み・隠蔽は、人格の問題ではなく設計への合理的反応
  • 設計①：個人成果と組織貢献の二階建て評価。貢献は性格ではなく、事実として確認できる行動で測る
  • 設計②：チーム目標の併用。全部チームにするとフリーライドが起きるため、個人主・チーム従の配合で調整する
  • 設計③：粗利ベースの達成率、解約の遡及控除など、計算式そのものに成果の質を織り込む
  • 継続・単価・紹介という時間軸の長い成果を評価に入れ、評価の時間軸をビジネスモデルと揃える
  • 制度変更は一気に行わない。現行の勝者への配慮、加点からの導入、トップセールスの巻き込みで移行を設計する
